## الجولة السادسة — T-09: عزل ffmpeg (Verified)

- `sandboxCommand` في `lib/engine/hardening.ts` يلفّ كل ffmpeg/ffprobe (عبر `hardenedSpawn` — التصدير والتحليل وMCP) بـ `unshare -r -n -m`: **لا شبكة** (net namespace فارغ) + **إخفاء** `.env*` وقاعدة SQLite (`/dev/null`) ومجلد المنزل (tmpfs). فشل أي إخفاء ⇒ لا تشغيل.
- `MONTAGE_FFMPEG_SANDBOX=auto|unshare|off`: `auto` يتدهور بلا عزل مع تحذير واحد إن كانت user namespaces معطّلة (مثل بعض حاويات/Ubuntu بـ AppArmor)؛ `unshare` يفرضه.
- الدليل: `tests/security/ffmpeg-sandbox.test.ts` (خادم HTTP محلي: خارج العزل يصل، داخله «NO-NET»؛ `.env.local` يُقرأ فارغاً وملف الوسائط عادياً؛ ffprobe/ffmpeg حقيقيان) — **تُتخطّى صراحةً** حيث لا namespaces. كل اختبارات التصدير/MCP/`ui:smoke` مرّت تحت العزل هنا. تصدير حقيقي: ffmpeg في net/user namespace مختلف عن الخادم، وسطر أوامره يبقى (قتل اليتيم يعمل).
- حدود صادقة: لا يمنع قراءة بقية نظام الملفات (bwrap لعزل كامل — غير مثبّت هنا للاختبار، لم يُنفَّذ).
- **إصلاح أثناء التحقق:** فتح قاعدة SQLite لأول مرة من عدة عمليات بالتزامن كان يفشل بـ «database is locked» (أعدتُ إنتاجه 22/30) فتسقط العملية صامتةً إلى «بلا قفل»؛ وترحيل المخطط كان يُقرأ خارج المعاملة. الآن: `busy_timeout` أولاً، إعادة محاولة الفتح، و`user_version` داخل `BEGIN IMMEDIATE` (0/40 فشل بأربع عمليات). اختبار القفل صار بأربع عمليات على قاعدة جديدة.
