مراجعة مشروع MontageAI

محرّر فيديو بالذكاء الاصطناعي — واجهة Next.js 14 + مسار مونتاج متعدد الوكلاء بلغة Python. مستودع MOT1209/EDITOR.AI، فرع main.

الحالة العامة: نموذج أوّلي متقدّم وسليم بنيوياً — يعمل محلياً، تغطية اختبار وCI جيدة، مع ملاحظات توثيق وتشغيل قابلة للمعالجة.

01 ملخص تنفيذي

المشروع تطبيق سطح مكتب/محلي لتحرير الفيديو آلياً. يتكوّن من جبهتين متكاملتين تتشاركان «عقد» بيانات واحداً (مخطط EDL):

  • واجهة Next.js 14 (App Router + TypeScript + Tailwind): محرّر تايملاين تفاعلي، ‏23‏ مسار API، ونظام مهارات (Skills) قابل للتوسعة.
  • مسار وكلاء Python في src/agents/: خمسة وكلاء تقودهم «المديرة التنفيذية» (CEO) عبر CrewAI، مع بوابات جودة مستقلة عن الإطار، وتدهور أنيق كامل عند غياب المفاتيح أو الشبكة أو GPU.

جودة الهندسة أعلى من المتوقّع لمشروع بهذا الحجم: فصل واضح للمسؤوليات، عقد بيانات مُتحقَّق منه آلياً بين اللغتين، CI بثلاث وظائف (اختبارات + بناء + حارس أسرار)، وتوثيق عربي غني (plan.md، ‏README‏ في الجذر وsrc/). النواقص الأساسية ليست في البنية بل في: تناقض بين وعد «المعالجة المحلية بالكامل» والاستدعاءات الفعلية لمزوّد LLM خارجي، وملف واجهة ضخم أحادي، وغياب اختبارات لطبقة TypeScript.

02 المعمار

مسار الوكلاء يمثّل سلسلة معالجة حقيقية — الترتيب يحمل معلومة، لذا يُعرض مرقّماً:

Analystffmpeg probe · صمت · Whisper كلمة-بكلمة · سكون/سواد · وجوه
Directorخطة EDL عبر LLM هرمي + خطة قواعد · طبقات جلوسة · B-Roll · ترجمات
Criticدرجة إبداعية ‏0–100‏ + حكم approve/revise + حلقة مراجعة
Audioخطة موسيقى + Ducking + مؤثرات + هدف LUFS (حتمي)
Renderكشف GPU حقيقي + بناء أوامر ffmpeg + تنفيذ الرندر

بين كل مرحلتين بوابة تحقّق (validation.STAGE_VALIDATORS) — دوال نقية على مُخرَج الوكيل، لا تعرف شيئاً عن CrewAI، وتبقى صالحة لو استُبدل الإطار. يتحقّق CI أن مجموعة البوابات مطابقة تماماً لترتيب المراحل.

FRONTEND · app/ · components/ · lib/

واجهة Next.js

  • components/editor/Editor.tsx — المحرّر الكامل (تايملاين، معاينة، أدوات).
  • ‏23‏ مسار API: /api/ai/* (تفريغ، ترجمة، مشاهد، وجوه، TTS…)، /api/agents/* (المسار الكامل)، /api/export/*، /api/skills.
  • نظام Skills: BaseSkill + ‏40‏ مهارة + SkillManager + Workflow (مسار افتراضي + Viral Shorts).
  • حفظ المشاريع في localStorage.

PIPELINE · src/agents/

مسار الوكلاء

  • ceo_agent.py — تنسيق هرمي، مع تدهور تلقائي hierarchical → sequential → قواعد محلية.
  • edl_schema.py — مخطط Pydantic (camelCase) هو العقد المشترك مع lib/agents/types.ts.
  • تكامل auto-editor (ثنائية اختيارية) لكشف السكون/السواد وتصدير NLE، مع احتياط ffmpeg كامل عند غيابها.
  • كل مخرجات المراحل تُحفظ في .montage_ai/pipeline/<job>/ للتشخيص بلا إعادة تشغيل.

03 الجودة والتحقق

حالة الفحوص وقت المراجعة (شُغّلت محلياً):

  • ✓ pytest — ‏24‏ حالة، كلها ناجحة (‏test_auto_editor‏ ‏14‏ + ‏test_critic_loop‏ ‏5‏ + ‏test_phase2‏ ‏4‏، بعد جمعها ‏24‏).
  • ✓ tsc --noEmit — نظيف، بلا أخطاء.
  • ✓ node scripts/check-contract.ts — ‏60‏ تحقّقاً، ‏0‏ أخطاء (Python superset مسموح).
  • ✓ CI .github/workflows/ci.yml — ثلاث وظائف: python-checks (compileall + pytest + تطابق الوكلاء/البوابات)، ts-checks (tsc + عقد)، secrets (gitleaks).
  • ⚠ لم يُنفَّذ next build الكامل في هذه المراجعة (اكتُفي بـ tsc).
  • ⚠ لا اختبارات لطبقة TypeScript إطلاقاً — SkillManager، Workflow، منطق التسميات، ومسارات API بلا تغطية.

04 الأمان

  • ✓ لا ملفات أسرار في Git — .env*.local و.env و.venv/ و.montage_ai/ مستثناة، وحارس gitleaks يعمل على كل دفع.
  • ✓ المفاتيح تُحلّ لكل طلب: ترويسة العميل (x-opencode-key…) ← ثم process.env — يسمح بمفتاح المستخدم دون تخزينه على الخادم.
  • ملاحظة: تمرير المفتاح في ترويسة من المتصفح مقبول لتطبيق محلي أحادي المستخدم، لكنه غير مناسب لأي نشر مشترك. يُنصح بتأكيد عدم كتابة الترويسات في أي سجل.
  • ملاحظة خصوصية: مسارات /api/ai/transcribe* و/api/ai/translate وتفريغ analyst_agent ترسل الصوت/النص إلى مزوّد خارجي (Groq/OpenAI-compatible). راجع البند التالي.

توثيق ‏README‏ يعِد بأن «كل المعالجة تتم محلياً… بدون رفع ملفات لسيرفرات خارجية»، بينما التفريغ الصوتي والترجمة والتخطيط الإبداعي تستدعي فعلياً مزوّد LLM سحابياً (Groq/OpenAI) وترفع الصوت المستخرج. صحّح صياغة ‏README‏ لتفرّق بين ما يعمل محلياً (ffmpeg، القص، الموسيقى، القواعد) وما يتطلب مفتاحاً سحابياً. مهم للثقة والخصوصية.
صيانة components/editor/Editor.tsx ملف واحد بطول ‏4363‏ سطراً — يحمل الحالة والتايملاين والمعاينة والأدوات والمودالات. قسّمه إلى وحدات (حالة/هوكس، تايملاين، شريط أدوات، لوحة المسار). يعيق المراجعة والاختبار ومساهمة أي مطوّر آخر.
إعادة إنتاج المستودع فيه pnpm-lock.yaml وpnpm-workspace.yaml، لكن CI و‏README‏ الفعلي يستخدمان npm install بلا package-lock.json — بناءات غير مثبّتة الإصدارات. اختر مدير حزم واحداً: إمّا الالتزام بـ pnpm في CI أيضاً، أو حذف ملفات pnpm وإضافة package-lock.json.
تشغيل /api/agents/pipeline يشغّل رندر ffmpeg فعلياً عبر child_process.spawn داخل مسار Next مع maxDuration=300. لن يعمل على بيئة serverless (Vercel) — مخصّص للتشغيل المحلي فقط. وثّق صراحةً أن المشروع «محلي التشغيل»، أو افصل المسار الثقيل إلى خدمة/عامل منفصل إن كان النشر السحابي هدفاً.
اختبار لا تغطية اختبار لطبقة TypeScript (Skills، Workflow، API). الاختبارات كلها Python. أضف Vitest/Jest لـ SkillManager/Workflow/lib/captions على الأقل — منطق أساسي بلا شبكة أمان.
نظافة المستودع ملفّا test_video.mp4 (الجذر) وtest_assets/test_video.mp4 ملتزمان في Git كأصول ثنائية مكرّرة. انقلهما خارج Git (Git LFS أو تنزيل عند الحاجة) وأبقِ واحداً فقط.
ميزات معلّقة identify_speakers/track_faces منفّذان مع احتياطات، لكن يعتمدان حزماً اختيارية (pyannote / opencv) غير مدرجة افتراضياً في requirements.txt (مُعلّقة كتعليقات). ميزة مقصودة (تدهور أنيق)، لكن وضّح في ‏README‏ ما الذي يتفعّل فقط بعد pip install إضافي.
توثيق مفقود plan.md يشير إلى docs/decisions/ (ADR) وهو غير موجود. أنشئه أو أزل الإشارة.

06 نقاط القوة

  • عقد بيانات مُتحقَّق آلياً بين Python وTypeScript — نادر في مشاريع بهذا الحجم، ويمنع انحراف الأنواع.
  • تدهور أنيق منهجي — كل تبعية خارجية (LLM، Pexels، GPU، auto-editor، pyannote) لها مسار احتياطي، والمسار لا ينهار.
  • بوابات جودة مفصولة عن الإطار — قرار معماري جيّد يبقي المنطق قابلاً للنقل.
  • قابلية تشخيص عالية — كل مرحلة تحفظ مخرجها JSON، فأي فشل يُحلَّل من الملفات.
  • CI حقيقي بثلاث طبقات دفاع منذ وقت مبكر، وحارس أسرار.
  • توثيق عربي متّسق عبر الكود والواجهة والخطط — مطابق للجمهور المستهدف.

07 توصيات مرتّبة بالأولوية

  1. صحّح وعد «محلي بالكامل» في README — فصل الميزات محلية-التنفيذ عن التي تتطلب مفتاح مزوّد سحابي، مع تنبيه خصوصية للصوت المرفوع.
  2. فكّك Editor.tsx إلى ‏4–6‏ وحدات بمسؤولية واحدة لكل منها؛ ابدأ باستخراج منطق الحالة إلى هوكس.
  3. وحّد مدير الحزم (pnpm أو npm) بين الجذر وCI وREADME، مع lockfile ملتزم.
  4. أضف اختبارات TypeScript (Vitest) لـ SkillManager وWorkflow وlib/captions، وأدخلها في وظيفة ts-checks.
  5. وثّق نموذج التشغيل صراحةً كـ «تطبيق محلي» (رندر ffmpeg داخل مسار Next لا يصلح لـ serverless)، أو افصل العامل الثقيل.
  6. نظّف الأصول الثنائية من Git وأضِف next build إلى CI لضمان بناء إنتاجي سليم.
  7. أنشئ docs/decisions/ بـ ADR واحد على الأقل (لماذا CrewAI، لماذا البوابات ككود) — المادة جاهزة في src/README.md.

08 الخلاصة

MontageAI مشروع هندسته أنضج من واجهته: مسار الوكلاء ونظام العقود والتدهور الأنيق والـ CI كلها في مستوى منتج، بينما الواجهة (ملف واحد ضخم، بلا اختبارات) والتوثيق (وعد المحلية) متأخّران قليلاً. لا توجد مخاطر أمنية حرجة. أهم خطوة تالية هي مواءمة الوعود التسويقية مع السلوك الفعلي، ثم تفكيك ملف المحرّر — وبعدها يصبح المشروع جاهزاً لمساهمين إضافيين ولإصدار «منتج كامل» كما يستهدف plan.md.
