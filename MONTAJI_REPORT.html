٢ رصد المشاكل (Known Problems)

8 مشاكل معروفة — مرتبة بالأثر. كلها موثقة في الكود أو هنا مع حلول مقترحة.

P1 تجاويف Whisper/المتحدثون/الوجوه في analyst_agent

transcribe_word_level و identify_speakers و track_faces ترفع NotImplementedError — تُلتقط كتحذيرات داخل التقرير (تصميم مقصود للتدهور الأنيق).
الأثر: لا ترجمات كلمة-بكلمة حقيقية من الصوت (الديمو يحقن كلمات مصنّعة)، ولا تمييز متحدثين، ولا تتبع وجه لتغذية crop تلقائي.

الحل: مفتاح Groq موجود ويشمل whisper-large-v3-turbo — الربط جاهز للتطبيق في ممر قادم.

P1 الرندر الفعلي معلّق في render_agent

الممر يبني أمر ffmpeg كاملاً (trim/zoompan/ASS/loudnorm/faststart) ويحفظه في render.json لكنه لا يشغّله — NotImplementedError مقصود.
الأثر: المسار ينتهي بخطة + أمر جاهز بلا ملف فيديو نهائي.

الحل: تنفيذ subprocess.run على build_command + متوازي للمقاطع.

P2 حد TPM المجاني في Groq (12k/دقيقة)

Process.hierarchical يستهلك ~6k رمزاً لكل استدعاء (قوالب المديرة + أدوات التفويض) → استدعاءات متعددة تتجاوز الحد.
الحل المطبَّق: تدهور تلقائي هرمي → sequential → قواعد محلية (CREWAI_PROCESS للتحكم). الهرمية الكاملة تعمل فقط مع ترقية Dev Tier أو مزوّد آخر.

P3 CrewAI لا يدعم Python 3.14

بيئة الجهاز الافتراضية 3.14.4 — CrewAI يتطلب ≤3.13. الحل المطبَّق: .venv مستقل بـ Python 3.10.11.
خطر: أي تشغيل بالثعبان الافتراضي يتجاهل CrewAI صامتاً (تدهور أنيق — لكن بلا LLM).

P3 الترميز cp1256 على Windows

الافتراضي في Git Bash/Windows يحوّل العربية في stdout إلى رموز مكسورة. الحل المطبَّق: python -X utf8 + PYTHONIOENCODING=utf-8 + reconfigure في utils.py. الممارسة موثقة في README.

P3 لا GPU → NVENC غير متاح

الجهاز بلا تسريع GPU؛ كشف NVENC الحقيقي يرجع false → libx264 (بطيء للفيديوهات الطويلة). التصميم سليم (رجوع تلقائي) لكن الإنتاج الفعلي يحتاج GPU أو سيرفر رندر.

P3 لا اختبارات آلية لوحدة Python

لا pytest حالياً — التحقق يدوي/حي. البوابات والمخطط دوال نقية مثالية للاختبار السريع.

P4 ESLint بطيء/يتعطل على هذا الجهاز

npm على OneDrive بطيء جداً (موثق سابقاً) — next lint علّق >300s. tsc نظيف يغطي أغلب القيمة، لكن فحص الـ lint اليدوي غير متاح بسهولة محلياً.
